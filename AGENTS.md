# FedorBot: память о проекте для агентов (Codex, Claude Code)

Этот файл — конспект для будущих сессий: что за бот, как он устроен, какие решения приняты и какие факты о Codex CLI проверены. Читать перед любой работой в репозитории. Пользовательская документация — `README.md`, пошаговая установка — `INSTALL.md`. Codex читает этот файл сам (AGENTS.md в корне репозитория), Claude Code — через `CLAUDE.md`, который его подключает.

## Происхождение и владельцы
- Бот — перенос Telegram-бота для Claude Code (репозиторий `NeuroWorknotNeo/VladMaks`, папка `bot/`, пакет `claude_telegram_bot`) на Codex CLI от OpenAI. Сделан 29.09.2026 по просьбе владельца исходного бота (VladMaks) для его друга Фёдора, у которого подписка ChatGPT и Codex. Задача была «точно такой же функционал», с одним исключением (см. ниже).
- Пользователь бота — Фёдор (сервер и подписка его). Ставит бота его друг, владелец VladMaks: в `ALLOWED_USER_IDS` — один ID (того, кто ставит), ID Фёдора владелец спрашивать не хочет (решение 29.09.2026). Фёдор пишет боту в общей группе: группа, куда бота добавил владелец, открыта для всех участников (см. «Открытые группы»). Все участники доверенные, поэтому **разделение пользователей бота и агента (CLAUDE_RUN_AS_USER, split-users.sh, sudo/env -i, общая группа, `_share_dir`) сознательно выброшено** — владелец сказал, что эта система безопасности не нужна. Не возвращать без прямой просьбы.
- Официального Telegram-плагина у Codex нет, поэтому «вариант A» исходного README (Channels) не переносился.
- Тексты бота и документация — по-русски. Коммиты — по-русски, первой строкой `bot: …`; перед коммитом прогонять тесты.
- После любого изменения кода или документации напоминать команду обновления на сервере: `bash /root/FedorBot/deploy/update.sh`.

## Как устроен (кратко)
- На каждое сообщение бот запускает `codex exec --json --skip-git-repo-check … -- -` (промпт — через stdin) в каталоге проекта; продолжение — `codex exec resume --json … -- <id> -`. Читает JSONL-события и показывает прогресс в редактируемом сообщении. `/new` сбрасывает сессию.
- Права: по умолчанию `--dangerously-bypass-approvals-and-sandbox` (`CODEX_SANDBOX=danger-full-access`): на сервере некому подтверждать команды, а песочница bubblewrap на Ubuntu 24.04+ не работает без разрешения user namespaces (см. факты). `workspace-write`/`read-only` задаются через `-c sandbox_mode=… -c approval_policy="never"` — у `codex exec resume` НЕТ флага `--sandbox`.
- Инструкции бота (Telegram, `TG_SEND_FILE`, предел хода, setsid для долгих задач) передаются `-c developer_instructions="…"` (TOML-строка, `toml_string()`) — ОДИНАКОВЫМИ в каждом запуске: новое значение при `resume` Codex не применяет до ближайшего сжатия, а после сжатия берёт значение текущего процесса. Проверено: попадают в запрос developer-сообщением ровно один раз, в том числе при `resume` и после сжатия.
- Ключ разговора — `chat_id` или `chat_id:thread_id` (тема форума): у каждого разговора свой проект, сессия, модель, усилия, очередь. Состояние — `state.json` (`chats` + `meta.rate_limits`).
- Модули: `config.py` (настройки, кнопки моделей, уровни), `codex_runner.py` (запуск, разбор событий, остановка SIGINT→SIGTERM→SIGKILL по группе процессов, `codex login status`), `app_server.py` (сжатие истории через `codex app-server`), `sessions.py` (журналы сессий: модель, контекст, лимиты, удаление), `bot.py` (команды, доступ, очередь, прогресс, доставка, /compact), `git_tasks.py` (без изменений относительно оригинала), `formatting.py`, `quota.py`, `redaction.py`, `state.py`.
- **Расход токенов.** В `turn.completed.usage` Codex присылает НАКОПЛЕННЫЙ итог по всей сессии (включая прошлые запуски после resume). Поэтому раннер до запуска читает итог из журнала сессии и вычитает (`_minus`). Не убирать — иначе счётчики в чате удваиваются.
- **Модель, контекст, лимиты** в JSONL-потоке `codex exec` не приходят. Бот берёт их из журнала сессии `$CODEX_HOME/sessions/ГГГГ/ММ/ДД/rollout-<время>-<id>.jsonl` (`sessions.py`): `turn_context.model`, уровень — `turn_context.collaboration_mode.settings.reasoning_effort` (null = по умолчанию модели), `event_msg/token_count` → `info.last_token_usage.total_tokens` (занятость контекста), `info.total_token_usage`, `info.model_context_window`, `rate_limits.primary/secondary` (`used_percent`, `window_minutes`, `resets_at` в секундах эпохи), `credits`, `plan_type`; сообщения пользователя — `event_msg/item_completed` с `item.type == "UserMessage"`.
- **/context** читает журнал, к модели не обращается. **/quota** (скрытая, только владельцу) показывает проценты и время сброса окон из последнего снимка `rate_limits` (бот хранит его в `state.json`).
- **/compact.** `codex exec` не выполняет слеш-команды (проверено: «/compact» уходит модели текстом). Поэтому два пути:
  1. `/compact` без аргументов — **сжатие средствами Codex** через `codex app-server` (JSON-RPC построчно по stdio, `app_server.py`): `initialize` → `initialized` → `thread/resume {threadId, excludeTurns: true, cwd, model?, developerInstructions}` → `thread/compact/start {threadId}` → ждать уведомление `turn/completed` (`turn.status`), факт сжатия — `item/completed` с `item.type == "contextCompaction"`, размеры — `thread/tokenUsage/updated` (`tokenUsage.last.totalTokens`, `modelContextWindow`) до и после. Сессия (thread id) остаётся прежней. `developerInstructions` передавать ОБЯЗАТЕЛЬНО: после сжатия Codex вставляет в историю значение текущего процесса, без него инструкции бота пропали бы. Проверено вживую на 0.159 (включая следующий `exec resume`). Протокол экспериментальный: при любой ошибке (`AppServerError`, `status != completed`) бот откатывается на путь 2 и пишет почему (`Job.note`). app-server не читает `CODEX_API_KEY`, только `auth.json`.
  2. `/compact что сохранить` (или откат) — **конспект**: задание `kind="compact"` просит модель через resume написать конспект разговора с учётом пожелания, бот кладёт его в `ChatState.compact_summary`, сбрасывает сессию, и следующее сообщение уходит в новую сессию с конспектом впереди (`COMPACT_CONTEXT_PREFIX`). `/new`, `/project`, `/clone`, `/task` конспект сбрасывают. Сжатие самого Codex пожеланий не принимает (для OpenAI это «remote compaction»), поэтому с аргументом — только конспект.
  Если журнал сессии пропал, `/compact` ничего не повторяет в новой сессии: сбрасывает сессию и говорит об этом. Автосжатие при заполнении окна (по умолчанию 90%) Codex делает сам.
- **/forget** удаляет каталог разговора, журналы его сессии (`sessions.delete_session_files`, в т. ч. `archived_sessions`) и запись состояния. Старые сессии после `/new` и `/compact` остаются в `~/.codex/sessions` (Codex сам их не чистит).
- **Субагенты.** События `collab_tool_call` (`tool`: spawn_agent/wait/…, `receiver_thread_ids`, `agents_states` со `status`) превращаются в живой список агентов в прогрессе (✅/⏳/❌). Схема сверялась по исходникам Codex; если в новой версии поля изменятся — править `CodexRunner._handle_collab` и тест `tests/test_agents.py`.
- **Картинки** из Telegram передаются и путём в тексте, и флагом `--image` (работает и с `resume`; флаги стоят до `--`, потому что у `exec` `--image` принимает несколько значений; у `resume` значения делятся запятой — имена загрузок бот чистит `safe_filename`, запятых в них нет).
- **Тихая новая сессия.** Если при `resume` Codex вернул в `thread.started` другой id (так бывает с `--last`/именем), раннер ставит `RunResult.new_thread`, бот сообщает о новой сессии и не вычитает итог прежней.
- **Отправка файлов в чат**: маркер `TG_SEND_FILE: <путь>`, только файлы внутри рабочего каталога и не из чёрного списка (`.env`, `auth.json`, ключи…), до 50 МБ, до 10 за ответ.
- **Открытые группы** (`state.meta["group_access"]`: `{"<chat_id>": "open"|"closed"}`, методы `Engine.group_mode/set_group_mode/move_group/prune_groups`). Нет записи — отвечаем только `ALLOWED_USER_IDS`. Если бота добавил или изменил его права (стал member/administrator) кто-то из `ALLOWED_USER_IDS` (обновление `my_chat_member`; `from_user` — кто изменил статус бота) и записи ещё нет, группа становится `open` (`AUTO_TEAM_CHATS=true`): бот пишет об этом в группе, а если он простой участник в режиме приватности (`get_me().can_read_all_group_messages` ложно) — просит сделать его администратором. Публичная группа (`chat.username`) автоматически становится `closed` (вступить может кто угодно), открыть — только явно. `/team` → `open`, `/team off` → `closed` (скрытая, только `ALLOWED_USER_IDS`); решение владельца последующие `my_chat_member` НЕ меняют. Бот ушёл из группы (`bot_in_chat`: не member/administrator и не restricted с `is_member`) — запись удаляется (повторное добавление владельцем снова откроет группу), задания чата останавливаются (`Engine.cancel_chat`). При запуске `prune_groups` проверяет `getChatMember` для каждой записи: Telegram хранит обновления сутки, и удаление бота при выключенном сервисе иначе потерялось бы. Не-владелец, добавивший бота, группу не открывает. Присутствие владельца в группе не проверяется: владелец может настроить группу для друга и выйти, группа остаётся открытой (так задумано, тест `test_group_stays_open_after_owner_leaves`). `ALLOWED_CHAT_IDS` по-прежнему решает, в каких чатах бот работает, открытость — только кто там может писать. Участникам открытой группы, как и `TEAM_CHAT_IDS`, недоступны личка и команды владельца. `my_chat_member` обязан быть в `allowed_updates` (`__main__.py`): иначе Telegram такие обновления даже не создаёт. Переход группы в супергруппу: Telegram присылает сообщение с `migrate_to_chat_id` в старый чат, с `migrate_from_chat_id` — в новый (автор — кто угодно или никто, поэтому `AccessMiddleware` пропускает их без проверки), затем `my_chat_member` для новой супергруппы; «бот вышел» для старой группы не приходит (tdlib/telegram-bot-api#266). Бот переносит запись (`open` или `closed`) на новый ID по любому из двух сообщений.
- **Затирание секретов** (`redaction.py`): точные значения `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `CODEX_API_KEY`, `GH_TOKEN`/`GITHUB_TOKEN`, строки с «key»/«token» из `~/.codex/auth.json` (файл перечитывается при изменении — Codex сам обновляет токены), плюс формы токенов Telegram, `sk-…` (с цифрой и заглавной буквой, чтобы не задевать имена веток), JWT (`eyJ….….…`), GitHub. Защита в глубину, не граница.

## Итоги независимой проверки кода (29.09.2026) — уже исправлено, не ломать
- Пропавшая сессия определяется ТОЛЬКО по точному тексту Codex в stderr (`MISSING_SESSION_MARKERS`: «no rollout found for thread id») и только если запуск упал до первого хода (`no_result`, `turns == 0`, не таймаут/не отмена). Широкие совпадения по «session … not found» выбрасывали живую сессию и перезапускали задачу.
- Подсказки «не авторизован / исчерпан лимит / переполнен контекст» ищут фразы только в тексте ошибки Codex (`codex_error_text`: сообщение `turn.failed` и строки `Error: …` из stderr), не в ответе модели.
- Снимок лимитов берёт время из строки журнала (`rate_limits_at`), `merge_snapshot` не даёт старому снимку перекрыть новый, а окно, чей `resets_at` прошёл, не считается израсходованным.
- `CodexRunner.run` при отмене задачи снаружи (CancelledError) сам завершает группу процессов; `/forget` сначала ждёт штатной остановки запуска и только потом отменяет воркер.
- `/forget` вызывает `codex delete --force <id>` (удаляет журнал и записи сессии в SQLite-базах Codex; без `--force` не работает без терминала), затем добивает оставшиеся файлы (`archived_sessions`). Журналы субагентов (отдельные thread) и `session_index.jsonl` не трогаются — известное ограничение.
- Расход токенов прерванных/упавших запусков считается по журналу сессии (итог после минус итог до). Токены субагентов идут в их собственные thread и в счётчики бота не попадают.
- В app-server `turn/completed` может прийти раньше ответа на `thread/compact/start` — клиент запоминает его в обработчике уведомлений.
- `/status` предупреждает, если в окружении задан `CODEX_API_KEY` (`codex login status` его не видит, а `exec` берёт первым).
- `deploy/codex-login.sh` считает провалом только `turn.failed` или отсутствие `turn.completed` (события `error` с «Reconnecting… N/5» — не провал), проверочный запрос ограничен `timeout 300`.

## Решения (не переспрашивать)
- Предел на один запрос — 3 часа (`CODEX_TIMEOUT_SECONDS=10800`), значение подставляется в инструкции агента.
- Показывать токены, а не деньги (у Codex нет стоимости в событиях, `SHOW_COST` не переносился).
- `/model` и `/effort` — кнопки. Кнопки моделей — по одной на семейство с ТОЧНЫМ именем последней версии: `gpt-6-astra` («GPT-6 Astra», самая сильная), `gpt-6-sol` («GPT-6 Sol», для кода), `gpt-6-luna` («GPT-6 Luna», быстрая) + «По умолчанию». При выходе новой версии семейства ЗАМЕНИТЬ строку в `DEFAULT_MODEL_BUTTONS`, сверяясь с `codex debug models` (модели с `"visibility": "list"`), не по памяти; тест `test_default_model_buttons_one_per_family`. `/model` принимает любое имя без пробелов (`is_model_name`).
- Уровни рассуждений на кнопках: low, medium, high, xhigh, max. Скрытый уровень `ultra` (у Codex — «Maximum reasoning with automatic task delegation», есть не у всех моделей) — только текстом `/effort ultra` (синоним `ultracode`, как в боте для Claude) и только для `ALLOWED_USER_IDS`.
- Скрытые команды (не в меню, только `ALLOWED_USER_IDS`): `/quota` (`/limits`), `/conversations`, `/effort ultra`, `/team` (`/team off`).
- Друзьям владельца ID не нужны: группа, куда бота добавил владелец, открыта для всех участников (`AUTO_TEAM_CHATS=true` по умолчанию). Прав владельца (личка, `/sh`, `/quota` …) участники не получают.
- `/sh` и `/git` — только владельцу. `/forget` без аргументов — любому допущенному, с ключом — только владельцу.
- Поиск в интернете включён по умолчанию (`CODEX_WEB_SEARCH=live` → `-c web_search="live"`).
- Обновление (`update.sh`) обновляет и Codex (официальный установщик), и systemd-юнит из репозитория.
- `StateStore.get()` отмечает время активности разговора (в оригинале `save()` ставил одно время всем — /conversations показывал одинаковые даты).

## Проверенные факты о Codex CLI (0.159.0, 29.09.2026)
Подробный отчёт с выдержками из исходников и живыми примерами — `docs/codex-cli-0.159-facts.md`.
- Установка: `curl -fsSL https://chatgpt.com/codex/install.sh | sh` (тот же скрипт — ассет `install.sh` в релизах GitHub); ставит `~/.local/bin/codex`, пакеты — в `~/.codex/packages/standalone`; `CODEX_NON_INTERACTIVE=1` убирает вопросы, `CODEX_RELEASE=x.y.z` — конкретная версия. Бинарник ~290 МБ.
- `codex exec [OPTIONS] [PROMPT]`: промпт аргументом или из stdin (`-`); если stdin открыт и промпт задан аргументом, stdin добавляется блоком `<stdin>` — поэтому бот всегда шлёт промпт через stdin. `codex exec resume [OPTIONS] [SESSION_ID] [PROMPT]`, `-` — из stdin. Флаги `--json`, `-m`, `-c`, `--image`, `--skip-git-repo-check`, `--ephemeral`, `--dangerously-bypass-approvals-and-sandbox`, `-o` есть у обоих; `--sandbox`, `-C`, `--color` — только у `exec`.
- JSONL: `thread.started {thread_id}` (при resume — тот же id), `turn.started`, `item.started/updated/completed {item}`, `turn.completed {usage: input_tokens (вместе с кэшем), cached_input_tokens, cache_write_input_tokens, output_tokens, reasoning_output_tokens}` — накопительно по сессии!, `turn.failed {error: {message}}`, `error {message}` (в т. ч. «Reconnecting... N/5 (…)»). Элементы: `agent_message {text}`, `reasoning {text}` (у GPT-6 конспекты рассуждений по умолчанию выключены), `command_execution {command: "/bin/bash -lc '…'", aggregated_output, exit_code, status}`, `file_change {changes: [{path, kind: add|delete|update}], status}`, `web_search {id, query, action}` (в JSON два ключа id — побеждает последний), `mcp_tool_call`, `todo_list {items: [{text, completed}]}`, `collab_tool_call`, `error {message}` (предупреждения, например о смене модели при resume).
- Пропавшая сессия при resume: код 1, событий нет, stderr `Error: thread/resume: thread/resume failed: no rollout found for thread id <id> (code -32600)` → бот начинает новую сессию.
- SIGINT: процесс завершается с кодом 1 без `turn.failed`; сессия остаётся возобновляемой (проверено).
- GPT-6 работают в «code mode» (инструменты через единый `exec`), но в JSONL команды всё равно приходят как `command_execution`.
- `codex login status` пишет в **stderr** (бот читает stdout+stderr): «Logged in using ChatGPT» / «Logged in using an API key - sk-proj-***…» / «Logged in using access token» (код 0), «Not logged in» (код 1). `CODEX_API_KEY`/`OPENAI_API_KEY` на `login status` не влияют, но `CODEX_API_KEY` в окружении `exec` переключает на оплату по API. `codex login --device-auth` — вход кодом устройства (сначала сбрасывает прежний вход; ссылка https://auth.openai.com/codex/device, код живёт 15 минут; в аккаунте ChatGPT должен быть включён «Settings → Security → Device code authorization», у рабочих пространств — администратором; если выключен, сервер молча отклоняет код и CLI ждёт 15 минут — learn.chatgpt.com/docs/auth, openai/codex#34817); обычный `codex login` поднимает приём ответа браузера на localhost:1455 (или 1457) — на сервере его пробрасывают SSH-туннелем; `--with-api-key` читает ключ из stdin. Токены ChatGPT Codex обновляет сам (за 5 минут до истечения или раз в 8 дней), перед обновлением перечитывает `auth.json` с диска — параллельные процессы друг другу не мешают. `auth.json`: `{"auth_mode": "apikey"|…, "OPENAI_API_KEY": …, "tokens": {…}}`.
- Адрес API переопределяется ключом `openai_base_url` (переменная `OPENAI_BASE_URL` в 0.159 НЕ действует). Для локальных проверок: `CODEX_API_KEY=fake codex exec -c openai_base_url="http://127.0.0.1:PORT/v1" …`.
- Песочница Linux — bubblewrap; на Ubuntu 26.04 в контейнере/VPS команды падают с `bwrap: setting up uid map: Permission denied` (AppArmor `kernel.apparmor_restrict_unprivileged_userns`). Поэтому по умолчанию `danger-full-access`.
- `-c` — глобальный флаг: если хоть один `-c` стоит после `resume`, все `-c` ДО `resume` отбрасываются. Бот ставит все флаги после `resume`. Флагов `-s`, `-C`, `--add-dir`, `-p`, `--color` у `resume` нет — `config.py` не пускает их в `CODEX_EXTRA_ARGS`.
- Codex сам дописывает в `~/.codex/config.toml` `[projects."<git root>"] trust_level = "trusted"`, когда работает с правом записи в git-репозитории; после этого для проекта включаются его `.codex/config.toml`, хуки и правила. Это нормально.
- Команды агента наследуют окружение бота целиком (кроме `TELEGRAM_BOT_TOKEN`, который бот убирает сам). Субагентов можно запретить `-c agents.enabled=false`.
- Модель по умолчанию — первая видимая по приоритету в каталоге (на 0.159: `gpt-6-astra`, её уровень по умолчанию `low`); для аккаунтов ChatGPT каталог присылает сервер (`models_cache.json`).
- Каталог моделей: `codex debug models` (JSON). На 29.09.2026 видимые: gpt-6-astra, gpt-6-sol, gpt-6-luna, gpt-5.6-sol/terra/luna, gpt-5.5; окно 272k (эффективное 95% = 258.4k); уровни low/medium/high/xhigh/max, у части моделей ещё ultra.
- Полезные ключи config (схема — ассет `config-schema.json` в релизе openai/codex): `developer_instructions`, `web_search` (disabled|cached|indexed|live), `sandbox_mode`, `sandbox_workspace_write.network_access`, `approval_policy`, `model_reasoning_effort`, `model_reasoning_summary`, `model_auto_compact_token_limit`, `compact_prompt`, `openai_base_url`.
- `codex exec` пишет в stderr служебные строки (`Reading prompt from stdin...`, предупреждения, логи `ERROR codex_api::…`); `clean_stderr()` убирает шум, остальное бот показывает только при ошибке.

## Как разрабатывать
- Тесты: `python -m pytest -q` (зависимости — `requirements-dev.txt`). Настоящий `codex` подменяется скриптом `FAKE_CODEX` из `tests/helpers.py`: печатает те же JSONL-события, ведёт журнал сессии (модель, накопительные токены, лимиты) и умеет прикидываться app-server для сжатия (`FAKE_APP_SERVER=ok|fail|crash`); аргументы, промпты и сообщения app-server пишутся в `codex-args.jsonl(.prompts|.appserver)` (`codex_calls()`, `codex_prompts()`, `app_server_log()`). Команды прогоняются через настоящий Dispatcher aiogram с `MockedSession` (`tests/test_handlers.py`); там же `make_membership` (обновление `my_chat_member`) и `make_migration` (переход в супергруппу).
- Новая настройка: `config.py`, `.env.example`, таблица в README, список `_CLEAR` в `tests/helpers.py`.
- Не запускать настоящий `codex exec` с реальными запросами без нужды (тратит лимиты подписки). Для проверки формата событий — фейковый сервер OpenAI Responses + `openai_base_url` (см. факты).
