# FedorBot — Codex (OpenAI) в Telegram: бот для VPS

Telegram-бот, который на вашем сервере запускает **Codex CLI** от OpenAI по подписке ChatGPT (Plus/Pro/Business) и умеет делать задачи в GitHub: ветка → правки → тесты → коммит → push → pull request. Это перенос бота для Claude Code с тем же набором возможностей, только «мозги» — Codex.

Пошаговая установка с нуля для пустого сервера — в [INSTALL.md](INSTALL.md).

---

## Как это устроено

```
 Telegram ──► бот на VPS (Python, aiogram) ──► codex exec --json ──► OpenAI (подписка ChatGPT)
                     │                               │
                     │                               ├── читает/правит файлы в ~/workspace/<проект>
                     │                               ├── git commit / git push / gh pr create
                     ▼                               ▼
             прогресс и ответ в чат              GitHub (ветка + pull request)
```

Нейросеть работает на серверах OpenAI. На VPS работает клиент Codex («руки»: история разговора, инструменты, git) и маленький бот, который превращает сообщения Telegram в запуски `codex exec` и отправляет ответы обратно. Каждое сообщение — отдельный запуск `codex exec` в каталоге проекта; диалог продолжается командой `codex exec resume <id сессии>`, поэтому Codex помнит всю переписку, пока вы не скажете `/new`.

Бот не ходит в API OpenAI сам и не хранит ваших ключей: авторизацией, моделями и лимитами занимается официальный Codex CLI.

---

## Что нужно от сервера

- **Расположение.** Codex и ChatGPT доступны не из всех стран: сервер должен быть в [поддерживаемой OpenAI стране](https://help.openai.com/en/articles/7947663-chatgpt-supported-countries) (ЕС — Германия, Нидерланды, Финляндия — или США). Из неподдерживаемого региона вход и запросы будут отклоняться.
- **RAM.** Сам `codex` лёгкий (100–300 МБ), бот ~60 МБ; память съедают команды, которые запускает агент (тесты, сборки, расчёты). Минимум 2 GB + swap, комфортно 4 GB.
- **CPU.** 1–2 vCPU достаточно: сервер в основном ждёт сеть.
- **Диск.** 20–40 GB SSD (Codex с помощниками ~400 МБ, остальное — репозитории).
- **ОС.** Ubuntu 22.04/24.04/26.04 LTS или Debian 12/13 (установщик рассчитан на apt и systemd; нужен Python 3.10+).
- **Сеть.** Исходящий HTTPS к `chatgpt.com`, `auth.openai.com`, `api.openai.com`, `github.com`, `api.telegram.org`. Входящие порты открывать не нужно: бот работает через long polling.

Типичный тариф «2 vCPU / 4 GB / 40 GB в ЕС» закрывает задачу полностью. Swap добавляет `deploy/add-swap.sh`.

## Что важно знать о подписке

- **Вход — аккаунтом ChatGPT.** Codex входит в планы Plus, Pro, Business, Edu и Enterprise. На сервере без браузера вход делается кодом устройства: `deploy/codex-login.sh` запускает `codex login --device-auth`, печатает ссылку и одноразовый код, вы подтверждаете вход в браузере на своём компьютере. Учётные данные Codex хранит в `~/.codex/auth.json` пользователя бота и **сам их обновляет**, перелогиниваться регулярно не нужно.
- **Платит подписка, а не API.** Если вместо входа через ChatGPT задать API-ключ (`codex login --with-api-key`, переменная `CODEX_API_KEY`), запросы пойдут по тарифам API. Бот показывает способ входа в `/status` и предупреждает в логе, если в окружении есть `CODEX_API_KEY`.
- **Лимиты подписки те же.** Бот не обходит лимиты плана: длинные задачи расходуют ту же квоту, что и работа в терминале (окно 5 часов и недельное). Сколько израсходовано и когда обновится, показывает скрытая команда `/quota` (см. ниже).
- **Только для своих.** Бот отвечает людям из белого списка `ALLOWED_USER_IDS` (обязателен) и участникам групп, куда его добавил владелец. Все они расходуют одну подписку.

## Возможности

- Обычные сообщения уходят в Codex в текущем проекте; сессия сохраняется между сообщениями (`codex exec resume`), `/new` начинает заново.
- `/context` показывает, сколько занято в контексте диалога (модель, токены из окна, сумма за сессию), `/compact` сжимает историю диалога средствами самого Codex (как `/compact` в интерактивном Codex) — диалог продолжается в той же сессии.
- Прогресс прямо в чате: одно сообщение редактируется каждые несколько секунд и показывает время, последние действия (`💻 Shell: pytest -q`, `✏️ Edit: src/app.py`, `🌐 WebSearch: …`), план агента, мысль модели (если она их присылает) и последнюю реплику.
- Многоагентные задачи: когда Codex запускает субагентов, прогресс показывает их живьём — «🤖 Агенты: N работают · M готово» и список со статусами ✅/⏳/❌.
- В итоге каждого запуска: время, число вызовов инструментов, точная модель и токены (`↑` вход вместе с кэшем, `↓` ответ); в `/status` накопленная сумма по разговору.
- Ответы конвертируются из Markdown в HTML Telegram (блоки кода, таблицы, жирный, ссылки) и режутся на сообщения по 4096 символов.
- `/task описание` — задача для GitHub: бот создаёт ветку `tg/<дата>-<slug>` от основной, Codex вносит изменения, гоняет тесты, коммитит, пушит и открывает pull request через `gh`. Следующие сообщения продолжают работу в той же ветке.
- Несколько проектов в `~/workspace`: `/projects`, `/project имя`, `/clone url`.
- Очередь заданий на каждый чат, `/stop` останавливает текущее (SIGINT → SIGTERM → SIGKILL) и чистит очередь, общий лимит параллельных запусков.
- Файлы и фото: входящие сохраняются на сервере, Codex получает путь, а картинки ещё и видит сам (удобно присылать скриншоты ошибок). Исходящие — Codex может прислать готовый файл (PDF, картинку, архив) прямо в чат: он помечает его строкой `TG_SEND_FILE: <путь>`, бот прикрепляет. Отправляются только файлы из рабочего каталога (`ALLOW_SEND_FILES`, по умолчанию включено).
- Работа в группах: в группе, куда бота добавил владелец, ему может писать любой участник (ID друзей не нужны); белый список чатов, можно отключить личные сообщения; обращение обычным текстом, через `/ask`, @упоминание или ответ на сообщение бота; в группах с темами у каждой темы свой проект, сессия и очередь.
- `/sh команда` и `/git …` для быстрых проверок (`/git log -5`, `/sh ls`).
- Белый список Telegram ID, `/project` не выходит за пределы workspace; секреты затираются в исходящем тексте, `/sh` — только для владельца.
- Устойчивость: если сессия на сервере пропала, бот сам начинает новую; таймаут запуска; systemd с `Restart=always`; повтор отправки при обрыве связи с Telegram.

## Команды

| Команда | Что делает |
|---|---|
| обычный текст | отправить в Codex (продолжение сессии) |
| `/ask текст` | то же самое явно; в группе работает даже без прав администратора у бота |
| `/t текст` | сообщение людям: бот его не читает и не отвечает |
| `/new` | начать новый диалог в текущем проекте |
| `/context` | сколько занято в контексте диалога: модель, токены из окна, сумма за сессию (данные из журнала сессии Codex, без обращения к модели) |
| `/compact` | сжать историю диалога средствами Codex, чтобы освободить контекст; диалог продолжается в той же сессии (бот показывает, сколько было и стало токенов) |
| `/compact что сохранить` | сжатие с пожеланием: Codex пишет конспект разговора с учётом просьбы, бот начинает новую сессию и отправляет конспект первым сообщением вместе с вашим следующим запросом (сжатие самого Codex пожеланий не принимает) |
| `/status` | проект, ветка, модель, сессия, песочница, авторизация, что выполняется |
| `/projects` | список каталогов в workspace |
| `/project имя` | выбрать проект (`/project .` — корень workspace) |
| `/clone url [имя]` | клонировать репозиторий (`/clone owner/repo` тоже работает) |
| `/task описание` | задача для GitHub: ветка → правки → тесты → коммит → push → PR |
| `/model` | кнопки выбора модели (GPT-6 Astra, Sol, Luna, по умолчанию); можно и текстом: `/model gpt-6-sol` или любое точное имя модели |
| `/effort` | кнопки выбора уровня рассуждений (low … max, по умолчанию); можно текстом: `/effort high`. Скрытый `/effort ultra` (максимум рассуждений с автоматическим делегированием субагентам, дорого по лимитам; синоним `ultracode`) принимается только от `ALLOWED_USER_IDS` |
| `/stop` | остановить текущее задание и очистить очередь; сессия сохраняется, следующее сообщение продолжит тот же диалог |
| `/forget [ключ]` | забыть разговор: удалить его каталог проектов, журнал сессии Codex и настройки (с подтверждением). Свой текущий разговор может забыть любой допущенный участник; форма с ключом (чужой разговор) — только `ALLOWED_USER_IDS` |
| `/sh команда`, `/git …` | выполнить команду в каталоге проекта (**только владелец** из `ALLOWED_USER_IDS`) |
| `/team`, `/team off` | (владелец, в группе; в меню нет) открыть группу для всех участников / снова отвечать только `ALLOWED_USER_IDS`. Обычно группа открывается сама, когда бота в неё добавляет владелец |
| `/id` | показать свой Telegram ID, ID чата и темы |

**После `/stop`.** Диалог не теряется: бот запоминает id сессии прерванного запуска, и следующее обычное сообщение («продолжай», уточнённая формулировка задачи) уходит в `codex exec resume`, модель видит всё, что успела сделать до остановки. Правки на диске и ветка, созданная `/task`, остаются. Сообщения, снятые из очереди, нужно отправить заново. Начать с чистого листа — `/new`; `/status` показывает, продолжается ли сессия.

**Модели.** Кнопки `/model` — по одной на семейство, у каждой точное имя последней версии: **Astra** — самая сильная (для сложных задач), **Sol** — рабочая лошадка для кода, **Luna** — быстрая и экономная. «По умолчанию» — модель, которую выбирает сам Codex (в версии 0.159 это GPT-6 Astra с уровнем рассуждений low; для аккаунтов ChatGPT список и выбор по умолчанию присылает сервер OpenAI). Уровень low быстрый, но для сложных задач лучше явно поставить `/effort medium` или `high`; выбранные модель и уровень запоминаются для каждого разговора. Список моделей, которые знает ваш Codex, показывает команда из INSTALL.md (шаг 11, `codex debug models`); новые модели иногда требуют свежей версии Codex — её ставит `deploy/update.sh`.

## Установка на VPS

Коротко (подробно, с объяснением каждого шага — в [INSTALL.md](INSTALL.md)):

1. Клонируйте репозиторий и запустите установщик от root:
   ```bash
   apt-get update && apt-get install -y git
   git clone https://github.com/NeuroWorknotNeo/FedorBot.git /root/FedorBot
   bash /root/FedorBot/deploy/install.sh
   ```
   Скрипт ставит зависимости и GitHub CLI, создаёт пользователя `codexbot`, копирует бота в `/opt/codex-telegram-bot`, делает venv, ставит Codex CLI официальным установщиком (`~/.local/bin/codex`) и регистрирует systemd-сервис `codex-telegram-bot`.
2. Войдите в Codex аккаунтом ChatGPT: `bash /root/FedorBot/deploy/codex-login.sh` (ссылка и одноразовый код — для браузера на вашем компьютере).
3. Дайте доступ к GitHub (для push и PR):
   ```bash
   sudo -iu codexbot gh auth login      # GitHub.com → HTTPS → Yes → Login with a web browser
   sudo -iu codexbot gh auth setup-git
   sudo -iu codexbot git config --global user.name  "Ваше имя"
   sudo -iu codexbot git config --global user.email "you@example.com"
   ```
4. Заполните `/opt/codex-telegram-bot/.env`: как минимум `TELEGRAM_BOT_TOKEN` и `ALLOWED_USER_IDS`.
5. Запустите: `systemctl start codex-telegram-bot`, логи — `journalctl -u codex-telegram-bot -f`. Напишите боту `/status`.

## Как ставить задачи для GitHub

```
Вы:   /clone owner/repo
Бот:  ✅ Клонировано в /home/codexbot/workspace/repo (ветка main) и выбрано как проект.

Вы:   /task добавь в Makefile цель clean, которая удаляет .aux/.log/.toc, и опиши её в README
Бот:  🌿 Создана ветка tg/20260929-1530-dobav-v-makefile-tsel-clean от main. Codex приступает к задаче…
      ⏳ Работаю… 0м 41с · инструментов: 6 · gpt-6-sol
      💻 Shell: cat Makefile
      ✏️ Edit: Makefile
      ✏️ Edit: README.md
      💻 Shell: make -n clean
      💻 Shell: git push -u origin tg/2026…
      💻 Shell: gh pr create --base main --title …
      ✅ Готово · 1м 12с · инструментов: 8 · токены ↑182.4k ↓3.1k · gpt-6-sol
      (отчёт Codex: что изменено, как проверено, хеш коммита, ссылка на PR)
      🌿 Ветка задачи: tg/… · Коммиты: …

Вы:   ещё добавь цель clean в корневой Makefile, если он есть
      (это же сообщение продолжит ту же сессию и ту же ветку; Codex допушит в тот же PR)
```

Правила, которые бот встраивает в задачу: работать только в созданной ветке, прогнать тесты/линтеры проекта, не коммитить секреты и артефакты, `git push -u origin <ветка>`, `gh pr create --base <основная>`, в конце короткий отчёт на языке задачи. Уточняющих вопросов Codex не задаёт (некому отвечать) — делает разумные допущения и перечисляет их.

`/task` требует чистого рабочего дерева: если предыдущая задача оставила незакоммиченные файлы, бот покажет `git status` и попросит разобраться (например, «закоммить всё» обычным сообщением или `/git stash`).

## Работа в группе

Бот может отвечать не в личных сообщениях, а в группе (или только в группе), например в общей с другом.

1. Создайте группу и добавьте в неё бота и друзей. Если бота добавили вы (кто-то из `ALLOWED_USER_IDS`), бот напишет, что отвечает всем участникам: ID друзей знать не нужно.
2. Сделайте бота администратором группы (права можно оставить минимальные). В режиме приватности Telegram передаёт боту в группе только команды и ответы на его сообщения; администраторы получают всё. Альтернатива: у @BotFather `/setprivacy` → Disable и заново добавить бота в группу.
3. Необязательно — ограничить бота этой группой: отправьте в ней `/id` (бот покажет ID чата вида `-1001234567890`), в `.env` добавьте `ALLOWED_CHAT_IDS=<ID группы>`; чтобы бот не отвечал в личке, поставьте `ALLOW_PRIVATE_CHATS=false`. Перезапустите сервис: `systemctl restart codex-telegram-bot`.
4. Если группа станет супергруппой (ID сменится на `-100…`), доступ для всех участников бот перенесёт сам, а `ALLOWED_CHAT_IDS` (если задан) нужно обновить: отправьте `/id` (в неразрешённом чате бот всё равно показывает ID), поправьте `.env` и перезапустите сервис.

Обращаться к боту в группе можно обычным текстом (по умолчанию бот обрабатывает все сообщения допущенных пользователей), командой `/ask текст`, упоминанием `@имя_бота текст` или ответом на его сообщение. Сообщение людям, а не боту, начинайте с `/t`. Если в группе больше человеческого общения, удобнее `GROUP_REQUIRE_MENTION=true`: обычный текст уходит в Codex только с упоминанием или ответом.

Реакции: приняв сообщение в работу, бот ставит 👀, после ответа меняет на 👍, при ошибке или остановке снимает (`REACTION_WORKING`, `REACTION_DONE`).

Кто может писать боту: пользователи из `ALLOWED_USER_IDS` — везде; в группе, которую открыл владелец, — любой её участник. Группа открывается сама, когда бота в неё добавляет или назначает администратором кто-то из `ALLOWED_USER_IDS` (`AUTO_TEAM_CHATS=true`, бот пишет об этом в группе); публичные группы (с @адресом) сами не открываются. Вручную — командой владельца `/team` в группе; закрыть — `/team off` (это решение сохраняется, пока владелец снова не отправит `/team`). Убрали бота из группы — бот её забывает и останавливает её задания. Текущий доступ показывает `/status` (строка «👥 Доступ»). Участникам открытой группы недоступны личка и команды владельца (`/sh`, `/git`, `/quota`, `/conversations`, `/forget ключ`, `/effort ultra`). Все участники группы пишут в один общий разговор (проект, сессия, очередь общие). Постоянные командные группы можно задать и в `.env` — `TEAM_CHAT_IDS`; в группах с темами каждая тема — отдельный разговор со своим проектом, сессией и очередью. `WORKSPACE_PER_CHAT=true` даёт каждому чату отдельный каталог `workspace/chat_<id>`.

## Уборка: удаление тем и разговоров

Об удалении темы Telegram боту не сообщает, поэтому её следы на сервере остаются: каталог `workspace/chat_<чат>_<тема>/` (при `WORKSPACE_PER_CHAT=true`), журнал сессии Codex в `~/.codex/sessions` и запись в `state.json`. Перед удалением темы отправьте в ней `/forget` и подтвердите кнопкой. Для уже удалённых тем есть скрытая команда `/conversations`: все известные боту разговоры с датой активности, проектом и размером на диске; ненужные забываются командой `/forget ключ`.

## Скрытая команда /quota

`/quota` (или `/limits`) показывает, сколько израсходовано и когда обновятся лимиты подписки ChatGPT:

```
⏳ Лимиты подписки
5-часовое окно: использовано 23%, обновление через 3ч 30м (29.09 21:00 MSK), данные 7м назад
недельное окно: использовано 41%, обновление через 1д 19ч (01.10 10:00 MSK), данные 7м назад
```

Источник — снимки лимитов, которые Codex получает от OpenAI вместе с ответами модели и записывает в журнал сессии; бот запоминает последний снимок в `state.json`. Пока запусков не было, команда так и скажет. Часовой пояс — `TIMEZONE`. Команды нет в меню, отвечает она только пользователям из `ALLOWED_USER_IDS`.

## Безопасность

Codex выполняется **от имени пользователя `codexbot`** и по умолчанию без песочницы (`CODEX_SANDBOX=danger-full-access`) — иначе на сервере некому подтверждать команды. Значит, **кто может писать боту, тот фактически имеет shell от `codexbot`** и может прочитать любой его файл, включая `.env` с токеном Telegram и `~/.codex/auth.json`. Бот рассчитан на владельца и пару доверенных людей, поэтому это сознательный компромисс: разделение на отдельных пользователей для бота и агента здесь не делается.

Что бот делает, чтобы снизить риск:
- **Белый список** `ALLOWED_USER_IDS` обязателен; чужим бот отвечает только на `/start` (в личке) и `/id`.
- **Группа, куда бота добавил владелец, открыта для всех её участников** — добавляйте бота только туда, где все свои. Закрыть группу — `/team off`, отключить автоматическое открытие — `AUTO_TEAM_CHATS=false`.
- **Затирает секреты в исходящем тексте**: точные значения `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `CODEX_API_KEY`, `GH_TOKEN`/`GITHUB_TOKEN`, токены входа из `~/.codex/auth.json` и строки, похожие на токены Telegram/OpenAI/GitHub, заменяются на `‹секрет скрыт ботом›`. Не ловит секрет, который модель преобразовала (перекодировала, разбила) — это защита в глубину, а не граница.
- `/sh` и `/git` — только для `ALLOWED_USER_IDS`; полностью отключить — `ALLOW_SHELL=false`.
- Файлы в чат отправляются только из рабочего каталога и никогда — `.env`, `auth.json`, ключи.
- Токен Telegram не передаётся в окружение `codex`, `.env` имеет права 0600 (но процесс того же пользователя всё равно может прочитать файл).

Держите на сервере только то, что не жалко доверить агенту. **Если токен мог утечь — сначала отзовите его**: Telegram — @BotFather → `/revoke` → новый токен в `.env` → `systemctl restart codex-telegram-bot`; вход Codex — `sudo -iu codexbot codex logout`, затем снова `deploy/codex-login.sh` (и завершите сеансы в настройках безопасности ChatGPT).

**Песочница.** `CODEX_SANDBOX=workspace-write` разрешает агенту писать только в каталог проекта (сеть — по `CODEX_NETWORK_ACCESS`). Песочница Codex в Linux использует bubblewrap и пространства имён пользователей, а на Ubuntu 24.04+ AppArmor по умолчанию их ограничивает — команды тогда падают с `bwrap: setting up uid map: Permission denied`. Поэтому по умолчанию песочница выключена; включать её — только проверив, что команды проходят (`/sh` не в счёт: он выполняется ботом без песочницы).

## Настройки

Все параметры — в `.env.example` с комментариями. Самые полезные:

| Переменная | Значение по умолчанию | Смысл |
|---|---|---|
| `TELEGRAM_BOT_TOKEN`, `ALLOWED_USER_IDS` | — | обязательные |
| `WORKSPACE_DIR` | `~/workspace` | где лежат проекты |
| `ALLOWED_CHAT_IDS` | пусто (любой чат) | в каких чатах отвечать; ID группы покажет `/id` |
| `TEAM_CHAT_IDS` | пусто | группы, где боту могут писать все участники |
| `AUTO_TEAM_CHATS` | `true` | группа, куда бота добавил владелец, открыта для всех участников; `false` — открывать только вручную (`/team`) |
| `ALLOW_PRIVATE_CHATS` | `true` | `false` — не отвечать в личных сообщениях |
| `WORKSPACE_PER_CHAT` | `false` | `true` — отдельный каталог проектов на каждый чат |
| `GROUP_REQUIRE_MENTION` | `false` | `true` — в группе реагировать на текст только при @упоминании или ответе |
| `CODEX_SANDBOX` | `danger-full-access` | песочница Codex: `danger-full-access` / `workspace-write` / `read-only` |
| `CODEX_NETWORK_ACCESS` | `true` | сеть внутри песочницы `workspace-write` |
| `CODEX_WEB_SEARCH` | `live` | поиск в интернете: `live`, `cached`, `indexed`, `disabled` (или `true`/`false`) |
| `CODEX_MODEL` | как решит Codex | модель для всех чатов (в чате: `/model`) |
| `MODEL_BUTTONS` | не задана: `default,gpt-6-astra:GPT-6 Astra,gpt-6-sol:GPT-6 Sol,gpt-6-luna:GPT-6 Luna` | кнопки `/model`. **Обычно не задают:** переменная перекрывает список из кода целиком, а `update.sh` файл `.env` не трогает |
| `CODEX_EFFORT` | как у модели | уровень рассуждений для всех чатов (в чате: `/effort`) |
| `CODEX_TIMEOUT_SECONDS` | `10800` (3 часа) | максимум на один запуск; по истечении бот убивает все процессы запуска |
| `MAX_CONCURRENT_RUNS` | `2` | сколько `codex` могут работать одновременно |
| `SHOW_TOKENS` | `true` | показывать в итоге токены |
| `REDACT_ENV_NAMES` | — | доп. имена переменных окружения, значения которых затирать в чате |
| `ALLOW_SEND_FILES` | `true` | разрешить отправку файлов в чат (`TG_SEND_FILE:`; только из рабочего каталога) |
| `REACTION_WORKING`, `REACTION_DONE` | `👀`, `👍` | реакции «принял в работу» и «ответил»; пусто или `off` — отключить |
| `TIMEZONE` | `UTC` | часовой пояс для времени в ответах (например, `Europe/Moscow`) |
| `CODEX_EXTRA_ARGS` | — | дополнительные флаги `codex exec`, обычно `-c ключ=значение` (например `-c model_reasoning_summary="auto"` — присылать конспекты рассуждений, `-c agents.enabled=false` — запретить субагентов); настройки чата (`/model`, `/effort`) имеют приоритет. Флаги, которых нет у `codex exec resume` (`-s`, `-C`, `--add-dir`, `-p` …), бот отклоняет |
| `CODEX_EXTRA_INSTRUCTIONS` | встроенный текст | дополнительные инструкции агенту (про Telegram, отправку файлов, предел хода); пустая строка — отключить |
| `TASK_AUTO_PR`, `TASK_BASE_BRANCH`, `TASK_BRANCH_PREFIX` | `true`, авто, `tg/` | поведение `/task` |

Постоянные инструкции для Codex по конкретному проекту кладите в `AGENTS.md` в корне репозитория — Codex читает его сам (а общие для всех проектов — в `~/.codex/AGENTS.md` пользователя `codexbot`).

## Обновление, логи, отладка

```bash
bash /root/FedorBot/deploy/update.sh                # git pull + свежий Codex + перезапуск сервиса
journalctl -u codex-telegram-bot -f                 # логи
sudo -iu codexbot codex login status                # чем авторизован codex
sudo -iu codexbot codex doctor                      # диагностика Codex
```

Частые проблемы:
- «Не найден исполняемый файл codex» — `bash /root/FedorBot/deploy/install-codex.sh` или задайте `CODEX_BIN=/home/codexbot/.local/bin/codex`.
- `/status` пишет «❌ не авторизован» или ответ Codex содержит `401 Unauthorized`, `refresh token`, `sign in again` — вход устарел или его не было: `bash /root/FedorBot/deploy/codex-login.sh`. Перезапускать бота после входа не нужно.
- Codex не может запушить — проверьте `sudo -iu codexbot gh auth status` и `git config --global user.email` под `codexbot`.
- `usage limit` / `rate limit` / «You've hit your usage limit» — исчерпан лимит подписки; `/quota` покажет, когда он обновится.
- «Codex ran out of room in the model's context window» — диалог заполнил окно контекста целиком (обычно Codex сжимает историю сам раньше). Сожмите вручную `/compact` или начните заново `/new`; бот подсказывает это прямо в ответе.
- «This session was recorded with model X but is resuming with Y» — вы сменили `/model` посреди сессии; это только предупреждение Codex. Для чистоты можно начать `/new`.
- Команды агента падают с `bwrap: setting up uid map: Permission denied` или `bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted` — включена песочница (`CODEX_SANDBOX=workspace-write`/`read-only`), а ядро не даёт bubblewrap создать пространство имён. Верните `CODEX_SANDBOX=danger-full-access`. Можно попробовать и разрешить песочницу (`apt install bubblewrap` или `sysctl kernel.apparmor_restrict_unprivileged_userns=0`), но это не проверялось.
- Бот молчит на запрос, а на следующее сообщение отвечает «📥 Поставлено в очередь» — запуск ждёт свободного слота (`MAX_CONCURRENT_RUNS`) или замка проекта; бот сразу пишет «⏳ Жду свободного слота», `/status` показывает «Ждёт свободного слота».
- `⏹ Прервано перезапуском бота` — запуск оборвал рестарт сервиса (обновление, падение, OOM). Отправьте запрос заново. Причины: `systemctl show codex-telegram-bot -p NRestarts`, `journalctl -k | grep -i 'killed process'`.
- `⏱ Остановлено по таймауту` — сработал `CODEX_TIMEOUT_SECONDS` (по умолчанию 3 часа). Долгую работу, которая должна пережить ход, агент уводит в `setsid nohup … &` (это прописано в его инструкциях); такая задача всё равно погибнет при перезапуске сервиса (`update.sh`).
- `❌ Внутренняя ошибка бота: … Cannot connect to host api.telegram.org` — обрыв связи с Telegram; бот повторяет отправку 5 раз с нарастающей паузой. Если повторяется постоянно, проверьте сеть: `curl -sS -o /dev/null -w '%{http_code}\n' https://api.telegram.org`.

Ручной запуск без systemd (для отладки):
```bash
cd /opt/codex-telegram-bot && sudo -u codexbot .venv/bin/python -m codex_telegram_bot
```

## Разработка и тесты

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты не ходят ни в Telegram, ни в OpenAI: `codex` подменяется скриптом, который печатает те же JSONL-события, что настоящий `codex exec --json` 0.159, и ведёт такой же журнал сессии (формат сверен с настоящим CLI).
